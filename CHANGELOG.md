## [Unreleased]
### Added
- **Вопросы Claude кнопками в Telegram** (2026-10-13): `AskUserQuestion` (один вариант, несколько вариантов, «Свой вариант», серия вопросов до 4) дублируется в Telegram, нажатие возвращается в сессию. Подкоманды `question` (← `PermissionRequest`, matcher `AskUserQuestion`) и `answered` (← `PostToolUse`). Работает параллельно с диалогом в терминале — кто ответил первым, тот и победил (проверено на живом Claude Code 2.1.294, в т.ч. при `bypassPermissions`). Один бот на несколько сессий и машин: чужие нажатия не подтверждаются, опрос `getUpdates` короткий (без 409). Флаг `~/.claude/telegram-question.on` (`ENABLE_QUESTIONS=0` в установщике — не включать), `TELEGRAM_QUESTION_TIMEOUT`.
- `docs/INTERNALS.md`: внутреннее устройство, проверенное поведение Claude Code и Telegram, замеры скорости, грабли, как проверять. `tests/e2e/tui-question.py` — сквозная проверка на живом Claude Code (после обновления Claude Code).
- `TELEGRAM_CURL_OPTS`: дополнительные опции curl для всех вызовов Bot API (например `--noproxy api.telegram.org`).
- **Навигация в серии вопросов**: кнопки «◀ Назад / Вперёд ▶», экран «Проверка» со сводкой и «✅ Отправить» (✏️ N — вернуться к вопросу); состояние каждого вопроса хранится отдельно, отметки чекбоксов и ответы не теряются. Двойной тап по «Вперёд» не перепрыгивает вопрос (кнопки устаревшего экрана отклоняются).
- `tests/question.bats` + `tests/mock-telegram.py`: тесты потока против mock Bot API (одиночный выбор, чекбоксы, свой текст, серия, ответ в терминале, чужие нажатия, 409, несколько сессий).
- Примитивы Bot API в `tg-notify-lib.sh`: `tg_api`, `tg_send_kb`, `tg_edit`, `tg_edit_kb`, `tg_cb_answer`, `tg_updates`, `tg_enabled`; база API переопределяется `TELEGRAM_API_BASE`.
- **Имя машины в уведомлениях** (2026-10-11): строка проекта — «📁 <папка> · MacBook Pro». Один бот на несколько компьютеров, без метки уведомления от них не различить. `tg_host` в `tg-notify-lib.sh`: на macOS — `scutil --get ComputerName` без префикса «<имя>’s », иначе `hostname -s`. Зовётся только при сборке сообщения (`stop` / `ask` / `chrome`), не на каждом хуке: `permit` висит на каждом `PreToolUse`.

### Changed
- **Репозиторий стал приватным** (2026-10-13): установка `curl | sh` с `raw.githubusercontent.com` недоступна, ставить из клона (`gh repo clone` → `./install.sh`); обновление — `git pull && ./install.sh`. Документация переписана под приватный репозиторий (в `docs/INTERNALS.md` можно хранить нестрашные секреты, но не токены).
- **Скорость вопросов**: длинный опрос `getUpdates` (до 5 с, `TELEGRAM_QUESTION_LONGPOLL`) вместо опроса раз в секунду; `answerCallbackQuery` и удаление служебных сообщений — в фоне; на пачку нажатий — одна правка сообщения, правка идёт в фоне параллельно следующему опросу (три быстрых нажатия по чекбоксам 4,3 → 3,1 с); опрос идёт фоновым `curl` + `wait`, поэтому SIGTERM (Esc) обрабатывается сразу. При ~1,2 с на вызов Bot API (VPN) на mock: нажатие → следующий экран 3,5–4,6 → 1,6 с, «Отправить» → решение хука 3,4 → 0,3 с.
- **Формат шапки всех сообщений** (2026-10-13): убрана верхняя полоса `━━━━━━━━━━━━━━━`; имя машины — отдельной строкой `💻` под папкой `📁` (раньше «📁 папка · MacBook Pro»). Касается «Завершено», «Нужно разрешение», «Нужно нажать Apply» и вопросов. Константа `TG_SEP` в библиотеке оставлена для сторонних хуков.
- `ask` (уведомление «Нужно разрешение») не дублирует вопрос, который уже ушёл в Telegram с кнопками; `prompt` / `stop` / `end` снимают состояние ожидающего вопроса.
- Название треда для шапки вынесено в функцию `session_title` (используют `stop` и `question`), поведение `stop` не изменилось.
- Варианты в сообщении-вопросе разделены пустой строкой (читаемость при длинных описаниях).
- Шапка вопроса выровнена с «Завершено» (пустые строки между блоками); строка 📋 с названием диалога выводится только когда оно есть — в свежей сессии она не дублирует папку.

### Fixed
- Вопросы: `Stop`, пришедший сразу после ответа в терминале, стирал состояние раньше, чем ждущий хук его читал, — сообщение получало «Вопрос закрыт» вместо ответа. Теперь состояние `done` (с pid хука) `Stop`/`prompt` не трогают, пока хук жив.
- README: пример `chat_id` заменён вымышленным значением.
- `install.sh`: запись хука через `$HOME` (ручная установка по `settings.hooks.json`) и тот же путь абсолютным теперь считаются одной записью — раньше установка поверх ручной регистрации задваивала хуки и все уведомления приходили дважды.

## [1.1.0] — 2026-10-10
### Changed
- **Семь скриптов объединены в один `tg-notify.sh`** (2026-10-10). Ветвление — по первому аргументу-подкоманде (`prompt` · `stop` · `permit` · `ask` · `chrome` · `end` · `debug`), библиотека `tg-notify-lib.sh` не менялась. Регистрация в `settings.json` теперь `sh "$HOME/.claude/hooks/tg-notify.sh" <подкоманда>`; `install.sh` и `settings.hooks.json` обновлены, `uninstall.sh` чистит и старые имена файлов (следы прежней установки). Поведение уведомлений сохранено один-в-один, проверено прогоном каждой подкоманды и установкой в изолированном каталоге.
- Подкоманда `chrome` (уведомление «Нужно нажать Apply в Chrome» и его гашение после успешного вызова) — раньше жила отдельным локальным файлом вне репозитория, теперь входит в общий скрипт.

### Fixed
- `stop.sh`: guard фоновых задач не распознавал инструмент `Workflow` (только Bash `run_in_background`) — формат `Workflow launched in background. Task ID: X` не совпадал с regex, заточенным под `Command running in background with ID: X`, и «Завершено» уходило раньше реального конца воркфлоу.

## [1.0.2] — 2026-06-26
### Added
- bats-тесты идемпотентности установщика (двойной `install` не плодит дубли, посторонние хуки не затрагиваются) + CI-workflow для них.
- `CHANGELOG.md`.

## [1.0.1] — 2026-06-26
### Changed
- `stop.sh`: заголовок треда не переводится, если он уже не на латинице (кириллица и т.п.) — русский заголовок не уходит в Google Translate впустую и не покидает машину.

## [1.0.0] — 2026-06-26
### Added
- Установщик `install.sh` (через `curl | sh` или из клона) и `uninstall.sh` (точечное удаление только своих хуков).
- Библиотека + шесть хуков: завершение сессии, запрос разрешения, синхронизация чата с терминалом (авто-удаление), опциональный отладочный.
- Секреты в `~/.claude/telegram-notify.env` (вне репозитория), с фолбэком на окружение.
- shellcheck CI; поддержка `CLAUDE_CONFIG_DIR` и установки из тега (`REF=`).
- `tg_send --max-time` (зависший Telegram API не блокирует Stop-хук); opt-out перевода (`TELEGRAM_TRANSLATE=0`).
- Guard фоновых задач: «Завершено» не уходит, пока в сессии есть незавершённые `run_in_background`.
