# 🔔 claude-code-telegram-notify

[![shellcheck](https://github.com/olegopro/claude-code-telegram-notify/actions/workflows/shellcheck.yml/badge.svg)](https://github.com/olegopro/claude-code-telegram-notify/actions/workflows/shellcheck.yml)
[![tests](https://github.com/olegopro/claude-code-telegram-notify/actions/workflows/test.yml/badge.svg)](https://github.com/olegopro/claude-code-telegram-notify/actions/workflows/test.yml)

Telegram-уведомления для [Claude Code](https://claude.com/claude-code) на хуках. Бот пишет в Telegram, когда длинная сессия завершилась или Claude просит разрешение на инструмент. А когда Claude задаёт **вопрос с вариантами ответа** — приходит сообщение с кнопками: нажатие уходит обратно в сессию, как будто ответили в терминале. Чат держится **синхронным с терминалом**: уведомление само исчезает, когда работа продолжена или сессия закрыта.

```
✅ Завершено · ~6 мин

📋 Рефакторинг модуля авторизации

📁 my-project
💻 MacBook Pro

🌐 https://claude.ai/code/session_015mgrRNaj8...
```

Вопрос Claude с кнопками (нажатие = ответ в сессию):

```
❓ Вопрос Claude · 1/2 · Формат

📋 Рефакторинг модуля авторизации

📁 my-project
💻 MacBook Pro

Как оформить результат?

1. Кратко — пара строк

2. Подробно — полный разбор с кодом

[1. Кратко]  [2. Подробно]
[✍️ Свой вариант]
◀ Назад / Вперёд ▶
```

## Возможности

- **Уведомление о завершении** длинной обработки (порог настраивается, по умолчанию 3 мин). Короткие ответы чат не засоряют.
- **Вопросы Claude кнопками.** Выбор одного варианта, несколько вариантов (чекбоксы), свой текст, серия вопросов — всё работает из Telegram, ответ возвращается в сессию. Терминал при этом остаётся рабочим: кто ответил первым, тот и победил. Подробности — [ниже](#вопросы-claude-в-telegram).
- **Зеркало терминала.** Пришло «Завершено» → продолжил диалог → уведомление удаляется. Пришло «Нужно разрешение» → одобрил инструмент → удаляется. Закрыл сессию → её уведомления стираются.
- **Не спешит с фоном.** Если turn закончился, но в сессии ещё работают фоновые задачи (`run_in_background`, `Workflow`) — «Завершено» ждёт их реального конца, а не шлёт раньше времени.
- **Перевод названия** треда на русский и **ссылка Remote Control** на сессию (если включён).
- **Имя машины** отдельной строкой под папкой проекта (`💻 MacBook Pro`) — один бот на несколько компьютеров, уведомления не путаются (на macOS — `ComputerName` без «<имя>’s », иначе `hostname -s`).
- **Секреты вне репозитория** — токен и `chat_id` лежат в локальном `~/.claude/telegram-notify.env`, который не коммитится (токены в git не кладём, даже когда репозиторий приватный).

## Установка

Нужны `jq` и `curl` (на macOS: `brew install jq`).

Репозиторий приватный (с 2026-10-13), поэтому ставится из клона — нужен доступ `gh`/git:

```sh
gh repo clone olegopro/claude-code-telegram-notify   # или git clone https://github.com/olegopro/claude-code-telegram-notify.git
cd claude-code-telegram-notify
./install.sh
```

> Однострочная установка `curl -fsSL https://raw.githubusercontent.com/olegopro/claude-code-telegram-notify/main/install.sh | sh`
> работает только пока репозиторий публичен: у приватного `raw.githubusercontent.com` отдаёт 404.

Установщик: кладёт хуки в `~/.claude/hooks/`, регистрирует их в `~/.claude/settings.json` (идемпотентно, с бэкапом `.bak`), создаёт шаблон `~/.claude/telegram-notify.env` и включает уведомления.

Опции через окружение:

```sh
WITH_DEBUG=1 ./install.sh   # + отладочный хук (лог событий)
ENABLE=0     ./install.sh   # установить, но не включать
# передать секреты сразу (иначе впишете в env-файл потом):
TELEGRAM_BOT_TOKEN=123:AAH... TELEGRAM_CHAT_ID=123456789 ./install.sh
```

## Получение токена и chat_id

1. **Токен.** В Telegram откройте [@BotFather](https://t.me/BotFather) → `/newbot` → задайте имя и username (заканчивается на `bot`). BotFather пришлёт токен вида `123456789:AAH...`.
2. **chat_id.** Напишите своему боту любое сообщение, затем выполните:
   ```sh
   curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates" | jq -r '.result[-1].message.chat.id'
   ```
   Придёт число — это ваш `chat_id`.
3. Сохраните секреты в `~/.claude/telegram-notify.env`. Выполните в терминале, подставив свои значения:
   ```sh
   cat > ~/.claude/telegram-notify.env <<'EOF'
   TELEGRAM_BOT_TOKEN=123456789:AAH...
   TELEGRAM_CHAT_ID=123456789
   EOF
   chmod 600 ~/.claude/telegram-notify.env
   ```
   Либо откройте файл редактором: `nano ~/.claude/telegram-notify.env`. Если запускали `install.sh`, файл уже создан (шаблон или заполнен из окружения) — останется вписать значения.
4. Перезапустите сессию Claude Code. Проверка отправки:
   ```sh
   . ~/.claude/hooks/tg-notify-lib.sh
   mid=$(tg_send "🧪 тест"); echo "message_id: $mid"; tg_delete "$mid"
   ```

## Настройка

| Что | Где | Значение |
|---|---|---|
| Вкл/выкл | файл-флаг `~/.claude/telegram-notify.on` | `touch` — включить, `rm` — выключить. Действует на все сессии сразу, без перезапуска. |
| Порог | `TELEGRAM_MIN_SECONDS` в env-файле | секунды: `180` = 3 мин, `300` = 5 мин. |
| Порог (мгновенно) | файл `~/.claude/telegram-min-seconds` | число секунд; читается с диска на каждый `Stop`, перебивает env без перезапуска. |
| Перевод заголовка | `TELEGRAM_TRANSLATE` в env-файле | `0` — не переводить заголовок треда (не отправлять его в Google Translate). По умолчанию переводится. |
| Отладка | файл-флаг `~/.claude/telegram-notify.debug` | при наличии хуки пишут лог событий в `/tmp/claude_notif_debug.log`. |
| Вопросы кнопками | файл-флаг `~/.claude/telegram-question.on` | `touch` — включить, `rm` — выключить (вопросы остаются в терминале). Нужен и `telegram-notify.on`. |
| Разрешения кнопками | файл-флаг `~/.claude/telegram-permission.on` | **выключено по умолчанию** (`touch` — включить, `rm` — выключить). См. [Разрешения кнопками](#разрешения-кнопками). |
| Ожидание ответа | `TELEGRAM_QUESTION_TIMEOUT` в env-файле | секунды, по умолчанию `3300`; должно быть меньше `timeout` хука в `settings.json` (3600). По истечении сообщение закрывается, вопрос остаётся в терминале. |
| Длинный опрос | `TELEGRAM_QUESTION_LONGPOLL` в env-файле | секунды, по умолчанию `5`: сколько `getUpdates` ждёт нажатия в одном запросе. Больше — реже запросы, но дольше реакция на закрытие вопроса в терминале. |
| Опции curl | `TELEGRAM_CURL_OPTS` в env-файле | добавляются ко всем вызовам Bot API; например `--noproxy api.telegram.org`, если прокси из окружения только замедляет (≈ −0,25 с на вызов). |
| Адрес Bot API | `TELEGRAM_API_BASE` в env-файле | по умолчанию `https://api.telegram.org`; нужен для тестов (mock-сервер) и зеркал. |

**Почему флаг-файл, а не env:** библиотека читается с диска на каждый хук, поэтому флаг подхватывают и уже запущенные сессии. Env кэшируется на старте сессии.

## Вопросы Claude в Telegram

Когда Claude вызывает инструмент `AskUserQuestion` (в терминале это диалог с вариантами), вопрос дублируется в Telegram. Что соответствует чему:

| В Claude Code | В Telegram |
|---|---|
| Один вопрос, 2–4 варианта | кнопки; нажатие сразу отправляет ответ |
| Несколько вариантов (чекбоксы) | кнопки-переключатели ☐/☑ и «✅ Готово»; ответ уходит списком через запятую |
| «Other» — свой текст | «✍️ Свой вариант» → ответом на сообщение пишется текст. Можно и просто ответить (reply) на сообщение с вопросом. В чекбоксах текст дописывается к отмеченным |
| Серия вопросов (до 4 в одном вызове) | одно сообщение, листается «1/3», «2/3»… кнопками **◀ Назад / Вперёд ▶** — ответы можно менять, отметки чекбоксов сохраняются. В конце экран «Проверка» со сводкой: **✅ Отправить** (появляется, когда отвечены все) или **✏️ 1, ✏️ 2** — вернуться к вопросу |
| «Chat about this», Esc | не переносятся — отвечайте в терминале, сообщение в Telegram закроется само |

Варианты в сообщении разделены пустой строкой — длинные описания читаются без труда.

**Кто ответил первым — тот и победил.** Диалог в терминале не блокируется: ответили там — сообщение в Telegram станет «🖥 Отвечено в терминале», ответили в Telegram — диалог в терминале закроется сам. Отдельное «Нужно разрешение» для такого вопроса не приходит (его заменяет само сообщение с вопросом).

### Как ответ возвращается в Claude Code

- Хук `PermissionRequest` (matcher `AskUserQuestion`) срабатывает сразу, как диалог показан, и идёт **параллельно** с ним (проверено на Claude Code 2.1.294, в том числе при `permissions.defaultMode: bypassPermissions`).
- Ответ хука — JSON `allow` + `updatedInput` с исходными `questions` и полем `answers` (`{"<текст вопроса>": "<метка>"}`, для чекбоксов — метки через `, `, для своего текста — сам текст). Claude Code применяет его так же, как ответ из диалога.
- Нажатия приходят **длинным опросом** `getUpdates` (до 5 с): ответ возвращается в момент нажатия. Хук подтверждает только **свои** обновления, чужие (другая сессия, другая машина на том же боте) не трогает. Если два хука опрашивают одновременно, Telegram обрывает старый запрос (409) — обновления не теряются, опрос повторяется чуть медленнее.
- Скорость: один вызов Bot API через VPN занимает ~1 с, поэтому нажатие → следующий экран ≈ 1,5 с (сеть до Telegram, а не хук). Ответ на кнопку и удаление служебных сообщений уходят в фоне, пачка нажатий даёт одну правку сообщения.
- Принимаются только нажатия и тексты из чата `TELEGRAM_CHAT_ID`.
- `PostToolUse` (matcher `AskUserQuestion`) сообщает ждущему хуку, что вопрос отвечен где-то ещё; сам Claude Code хук при ответе в терминале не останавливает.

Ограничения:

- в неинтерактивном режиме `claude -p` инструмента `AskUserQuestion` нет вовсе (там и вопросов нет);
- вопросы забирают обновления бота через `getUpdates`: если у бота настроен вебхук или его опрашивает кто-то ещё долгим запросом (например, официальный Telegram-канал Claude Code `--channels`), кнопки не сработают (409) — ответить можно в терминале; снять вебхук: `curl "https://api.telegram.org/bot<ТОКЕН>/deleteWebhook"`;
- сообщения боту, не являющиеся ответом на вопрос, хук отбрасывает (подтверждает и не читает).

### Проверка без Claude Code

Отправляет в Telegram тестовый вопрос и печатает решение хука после нажатия (ждёт минуту):

```sh
printf '%s' '{"session_id":"selftest","tool_input":{"questions":[{"question":"Кнопки работают?","header":"Тест","multiSelect":false,"options":[{"label":"Да","description":"пришло"},{"label":"Нет","description":"что-то не так"}]}]}}' \
  | TELEGRAM_QUESTION_TIMEOUT=60 sh ~/.claude/hooks/tg-notify.sh question
```

## Разрешения кнопками

Когда Claude Code спрашивает разрешение на инструмент (Bash, Write, Edit, MCP…), в Telegram приходит
не безликое «Claude needs your permission», а сообщение с инструментом и командой и кнопками:

```
🔔 Нужно разрешение

📁 my-project
💻 MacBook Pro

Bash
git push origin main
Отправить ветку

[✅ Разрешить]  [❌ Отклонить]
[✍️ Отклонить с причиной]
```

- **Разрешить / Отклонить** — решение возвращается в Claude Code; «Отклонить с причиной» — ответом на
  подсказку пишется причина, Claude её увидит.
- Диалог в терминале остаётся: кто ответил первым, тот и победил. Решили в терминале — сообщение станет
  «🖥 Решено в терминале».
- **Решения «по умолчанию» нет:** сбой, таймаут, закрытый терминал или недоступный Telegram — хук ничего не
  решает, диалог остаётся как есть. Обычное сообщение-ответ на запрос (например, «ок») тоже ничего не решает.
- Не обрабатываются `AskUserQuestion` (его ведут вопросы) и `ExitPlanMode` (план — только в терминале).
- Если в одной сессии одновременно ждут два запроса разрешения, кнопки получает первый; второй — в терминале.

> ⚠️ **Безопасность.** Включив функцию, вы разрешаете одобрять запуск команд из Telegram: решать сможет любой,
> у кого есть доступ к вашему чату с ботом. Принимаются только нажатия из чата `TELEGRAM_CHAT_ID`, но чат —
> это ваш Telegram-аккаунт, поэтому держите на нём двухфакторную защиту. Поэтому функция **выключена по
> умолчанию**: `touch ~/.claude/telegram-permission.on` включает её (установщик — `ENABLE_PERMISSIONS=1`).

## Как это работает

Хуки в `~/.claude/hooks/` (общая библиотека + скрипт с подкомандами):

| Событие | Хук | Действие |
|---|---|---|
| `UserPromptSubmit` | `tg-notify.sh prompt` | удаляет прошлые уведомления сессии (диалог продолжен), ставит метку времени старта |
| `Stop` | `tg-notify.sh stop` | если обработка дольше порога и фон завершён — шлёт «Завершено», запоминает `message_id` |
| `Notification` | `tg-notify.sh ask` | шлёт «Нужно разрешение» при запросе доступа к инструменту |
| `PreToolUse` | `tg-notify.sh permit` | инструмент начал выполняться → удаляет уведомление «Нужно разрешение» |
| `PreToolUse` + `PostToolUse` (matcher на chrome) | `tg-notify.sh chrome` | первый вызов Chrome в сессии → «Нужно нажать Apply»; успешное завершение → гасит его |
| `PermissionRequest` (matcher `AskUserQuestion`) | `tg-notify.sh question` | вопрос Claude → Telegram с кнопками; ответ возвращается решением хука |
| `PermissionRequest` (любой инструмент) | `tg-notify.sh permission` | запрос разрешения → Telegram с кнопками «Разрешить/Отклонить»; решение возвращается хуком (только при `telegram-permission.on`) |
| `PostToolUse` (любой инструмент) | `tg-notify.sh answered` | запрос решён (терминал/Telegram/Remote Control) → ждущий `question`/`permission` прибирает сообщение; «свой» запрос узнаётся по отпечатку инструмента и ввода |
| `SessionEnd` | `tg-notify.sh end` | сессия закрыта → удаляет оставшиеся уведомления и чистит `/tmp` |
| `PreCompact`/`SessionStart` | `tg-notify.sh debug` | опционально (`WITH_DEBUG=1`): лог событий, на уведомления не влияет |

Путь к транскрипту и `session_id` приходят хуку на stdin; папка проекта — в `$CLAUDE_PROJECT_DIR`. Время старта хранится в `/tmp/claude_notif_<session_id>`, отправленные `message_id` — в `/tmp/claude_notif_msg_<session_id>`, состояние ожидающего вопроса — в `/tmp/claude_tg_q_<session_id>`.

### Почему «Завершено» не приходит раньше времени

`Stop` срабатывает на конце **turn**, а фоновые задачи (`run_in_background`, инструмент `Workflow`) живут дальше и реактивируют сессию позже. Подкоманда `stop` сверяет транскрипт: запущенный фоновый ID (Bash — `Command running in background with ID: X`, Workflow — `Workflow launched in background. Task ID: X`) против метки завершения `<task-id>X</task-id>`, общей для обоих механизмов. Есть незакрытый — уведомление откладывается до финального `Stop`, когда фон вернулся и обработан.

## Обновление и удаление

Обновить — подтянуть клон и повторить установку (идемпотентно):

```sh
git pull && ./install.sh
```

Удалить (хуки из `settings.json`, файлы, флаги; секреты сохраняются):

```sh
./uninstall.sh
```

## Если не работает

- **Нет уведомлений** — проверьте флаг: `ls ~/.claude/telegram-notify.on` (нет файла → бот молчит), затем `tg_send`-тест из шага 4.
- **`jq: command not found`** — нужен `jq` (1.6+): `brew install jq`.
- **Сообщение не уходит** — неверный токен/`chat_id` в `~/.claude/telegram-notify.env`, либо Telegram недоступен (нужен прокси через `HTTPS_PROXY`).
- **Двойные уведомления** — в `settings.json` задвоилась регистрация хуков (например, осталась старая ручная запись через `$HOME` рядом с записью install.sh по абсолютному пути). Уберите дубли или переустановите начисто (`uninstall.sh` → `install.sh`).
- **Вопрос пришёл без кнопок / кнопки не отвечают** — проверьте `ls ~/.claude/telegram-question.on`, что сессия запущена после установки (хуки читаются при старте) и что у бота не включён вебхук (`curl "https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo"`). Для отладки: `touch ~/.claude/telegram-notify.debug` и смотрите `/tmp/claude_notif_debug.log` (строки `question …`).
- **Заголовок не переведён** — нет сети/таймаут переводчика, либо `TELEGRAM_TRANSLATE=0`; приходит оригинал.
